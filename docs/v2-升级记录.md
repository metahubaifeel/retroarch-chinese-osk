# v2 升级记录（1515 字 + 完整 assets）

## 一、修掉了字表生成器的分页 bug

**现象**：生成器报「1515 个字」，实际只写出 1183 个，丢 332 个。

**根因**：`生成中文键盘页.py` 里每页只塞 29 个汉字（第 2/3 行各 10 个 + 第 4 行 9 个），
但算页数用的是 `ceil(总数 / 40)` —— 每页浪费 11 格，末尾整页被吞。

**修法**：每页改成 4 行 × 10 个 = 40 格汉字，功能键放每行末位，
`CHARS_PER_PAGE` 与实际塞入数严格对齐，并在收尾做 `written == total` 断言。

```
修前： 44 页 / 1183 字（缺 332）
修后： 63 页 / 1515 字（一个字不丢）
```

丢过的字包括：事 速 数 蛇 上 旅 术 进 失 索 乱 翼 …
影响：13.9% 的游戏名里至少有一个字点不出来。

## 二、同步改了 3 处（页数变了就得一起改）

| 文件 | 内容 |
|---|---|
| `input/input_osk.h` | enum 的 `OSK_CHINESE_*` 条目：45 → 64 |
| `input/input_driver.c` | `osk_chinese_first_page[26]` 首指针表：i/u/v → `OSK_TYPE_UNKNOWN` |
| `menu/menu_driver.c` | `switch` 的 case：45 → 64 |

`tools/升级字表.py` 就是干这个的：从新头文件解析页清单，自动重生成这三处，
并做三方一致性断言（枚举 == switch == 头文件数组，差集为空）。

**踩过的坑**（都写进脚本注释了）：
1. 不能用非贪婪 `.*?` 匹配 switch 块 —— 会在第一个 `break` 就停，只换掉 2 个 case
2. 枚举名必须带 `OSK_` 前缀，且要和 switch 用同一套命名
3. 生成的头文件里**不要**再输出 `osk_chinese_first_page` —— `input_driver.c` 里有同名表，
   类型不同会编译失败

## 三、补上 assets（这是让 APK 真正可用的关键）

**现象**：第一次编出来的 APK 只有 7.1 MB（官方 150+ MB），装上去是个空壳 ——
菜单没图标、没着色器、没手柄自动配置。

**根因**：`/pkg/android/phoenix/assets/` 在 RetroArch 仓库的 `.gitignore` 里，
官方打包时从 5 个外部仓库（retroarch-assets / common-shaders / common-overlays /
joypad-autoconfig / libretro-database）灌进去，这部分脚本不在本仓库。

**修法**：直接从手机上官方 RetroArch 的 APK 里抽 assets。

```bash
# 官方 APK 里的结构：
#   assets/assets/      菜单主题 (glui/xmb/ozone)
#   assets/autoconfig/  手柄配置
#   assets/database/    游戏数据库
#   assets/shaders/     着色器
#   assets/overlays/    遮罩
#   assets/filters/  assets/info/

adb pull $(adb shell pm path com.retroarch.aarch64 | sed 's/package://') base.apk
unzip -q base.apk 'assets/*' -d /tmp/ra-assets/
cp -r /tmp/ra-assets/assets/* <RetroArch>/pkg/android/phoenix/assets/
# ⚠️ 注意层级：gradle 的 assets.srcDirs = ['assets'] 会把该目录【内容】当 APK 的 assets/
#    所以 phoenix/assets/ 下应该直接是 assets/ autoconfig/ database/ ... 不要再套一层
```

**结果**：APK 7.1 MB → **167.7 MB**，assets 项数与官方一致（9489 项）。
