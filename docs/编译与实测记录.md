## 一、本地编译验证（改动的 C 代码）

先单独编改动的两个目标文件，确认语法/枚举/数组尺寸都没问题：

```bash
./configure
grep -n HAVE_LANGEXTRA config.h
#  101:#define HAVE_LANGEXTRA 1        ← 默认就开了

make obj-unix/release/input/input_driver.o obj-unix/release/menu/menu_driver.o
#  CC input/input_driver.c
#  CC menu/menu_driver.c
#  make exit=0
```

`-Wall -Wextra` 下**零报错零警告**（只剩 `input_null_init` 那类原有的 unused parameter）。

### 四项交叉核对

1. **每页 44 格** —— 给 45 个数组各生成一个 C89 静态断言
   `typedef char assert_x[(sizeof(x) == 44*sizeof(char*)) ? 1 : -1];`，
   全部编译通过，运行时 `sizeof` 返回 44。
2. **数据真的进了目标文件** —— 在 `menu_driver.o` 里按 **UTF-8 原始字节**比对：
   头文件里 1183 个汉字**全部找到**。
   （注意：`strings` 默认最小长度 4，3 字节的汉字会被漏掉，得直接搜原始字节。）
3. **枚举 ↔ 数据 ↔ 编译产物 三方一致** —— 数据头 45 页、枚举 45 个 `OSK_CHINESE_*`，
   集合相同、顺序相同；从 `input_driver.o` 的 `.rodata` 里 dump 出
   `osk_chinese_first_page` 表（`nm` 可见，偏移 `0x400`），26 个值与数据推导出的完全相等，
   i / u / v 正确指向 `OSK_TYPE_UNKNOWN`。
4. **开关没漏** —— `gcc -E` 带 `-DHAVE_LANGEXTRA` 时表被引用 2 次、
   `OSK_CHINESE_INDEX` 5 次；**不带时都是 0 次**，不带开关也能编过 ——
   关掉 langextra 的构建完全不受影响。

## 三、缺口 1：APK 里没有 assets

编出来只有 7.1 MB，官方 RetroArch APK 是 150 MB 上下。差的不是编译失误 ——
源码树里**根本没有** `assets` 目录：

```
pkg/android/phoenix/assets/   在仓库 .gitignore 第 153 行里
```

官方打包时是从 5 个外部仓库灌进去的：

- retroarch-assets（xmb / ozone / glui 菜单主题）
- common-shaders
- common-overlays
- joypad-autoconfig
- libretro-database

**那个打包脚本不在本仓库里**（在官方 buildbot 侧）。

**实际影响**：新包名 = 全新数据目录，装上是个「空壳」：
三套菜单主题、着色器、遮罩、手柄自动配置、core 信息库、缩略图数据库都没有。
程序能启动、中文键盘能用、游戏能跑（rgui 菜单是代码画的，不依赖 assets），
但菜单会缺图标和主题。

**两条补法**：

1. **塞进 APK**（一劳永逸，要重编）—— clone 那 5 个仓库到 `media/` 下，按 Android
   需要的目录结构放进 `pkg/android/phoenix/assets/`，重跑 `assembleAarch64Release`。
   注意：Android 版 assets 的**确切摆放结构由官方 buildbot 脚本决定**，那个脚本不在
   本仓库，放之前得先摸准。
2. **指到手机上现成的**（不用重编）—— 新 App 里 Settings → Directory → Assets
   指向官方版已在用的 assets 目录，配合 MANAGE_EXTERNAL_STORAGE 权限直接读。
   存档 / 游戏列表同理要指过去。

## 四、缺口 2：真机没测成

设备连上了，包名版本都核对过：

```
$ adb devices -l
192.168.x.x:41951   device product:atom model:M2004J7AC
```

但安装被 MIUI 拦死，四条路同一个错：

```
$ adb install -r RetroArch-CN-aarch64-v8a-release.apk
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]

$ adb install -r --user 0 ...          → 同上
$ adb push ... && pm install -r ...    → 同上
$ pm install -i com.android.vending …  → 同上
```

而且盯着屏幕截了图：**手机上连确认弹窗都不弹** —— MIUI 是静默拒绝，不是等用户点。

第二个坑：**adb 模拟点击也被禁**

```
$ adb shell input keyevent KEYCODE_BACK
java.lang.SecurityException: Injecting to another application requires INJECT_EVENTS permission
```

两个其实是**同一个开关**管着：**设置 → 更多设置 → 开发者选项 →「USB调试（安全设置）」**
（有的版本显示为「通过USB安装」）。装应用和模拟点击都是它放行。
MIUI 可能要求登录小米账号 + 插 SIM 卡才允许打开。

**所以：这套键盘「能编译、数据正确、进了二进制」，但「点上去好不好用、
翻页顺不顺手」没有任何真机验证。**
