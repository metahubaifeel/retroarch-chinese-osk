# RetroArch 菜单搜索支持中文 —— 研究报告

> 调查日期：本次 session
> 目标设备：Redmi 10X 5G（天玑820 / Android 12 / MIUI 13）
> 结论：**可以做，社区没人做，改动量很小（估计 150-300 行）**

---

## 一、问题现象

RetroArch 的菜单搜索框**只能输入英文/数字/符号**，打不出汉字。
用户 5,525 个游戏里 3,813 个是中文名，**搜不了**。

---

## 二、根本原因（已从 APK 二进制验证）

```
RetroArch 的菜单搜索 = menu_input_dialog（自绘键盘）
                    ↓
它不调用 Android 的 InputMethodManager / showSoftInput
                    ↓
拿不到系统输入法（Gboard / 讯飞）的输出
                    ↓
所以只能输入键盘自带格子上的字符
```

**验证方法**（本次实际执行）：
```bash
# 从 APK 抽出 dex 和 so，搜 IME 相关符号
adb pull $(pm path com.retroarch.aarch64) base.apk
unzip base.apk classes*.dex lib/arm64-v8a/libretroarch-activity.so
strings classes*.dex | grep -iE "InputMethod|showSoftInput|InputMethodManager"
  → 只有 attemptToggleImmersiveMode（那是状态栏切换，不是输入法）
strings libretroarch-activity.so | grep -iE "input_method|show_soft|soft_keyboard"
  → 只有 frame_time / time_get 之类的误匹配，无 IME 接口
```

**结论：RetroArch Android 完全没有接 Android 输入法。**

## 四、设备端验证（Redmi 10X 实机）

从手机上抽出的 `libretroarch-activity.so`（17.4 MB）里扫描：

| 检查项 | 结果 |
|---|---|
| `input_event_osk_append` 符号 | ✅ 存在 |
| 韩文字母 `ㄱㄲㄴㄷㄸㄹㅁㅂㅃ` | ✅ 存在（说明 `HAVE_LANGEXTRA` 是开的）|
| 日文假名 | ✅ 存在 |
| 中文键盘页 | ❌ 不存在 |
| `InputMethodManager` | ❌ 不存在 |

**结论：Android 版的 `HAVE_LANGEXTRA` 已经开启，韩文/日文页都能用。
只差一个中文页 —— 纯粹是"没人写"，不是"做不到"。**

## 五、为什么没人做中文

**因为中文和韩文/日文的难度不是一个量级：**

| 语言 | 字符数 | 能否塞进 44 格 |
|---|---|---|
| 韩文 | 24 个基本字母（组合成音节）| ✅ 轻松 |
| 日文假名 | 46 平 + 46 片 | ✅ 两页搞定 |
| **中文** | **常用 3,500 / 全部 20,000+** | ❌ 不可能 |

**韩文/日文一个人几天就能做完；中文要么做几百页，要么接系统输入法。**

**这是个"没人愿意啃"的活 —— 技术上完全可行。**

## 六、可行方案（三条路）

### 方案 A：拼音首字母索引页（**最推荐**）

**设计：**
```
第 0 页：26 个拼音首字母（a-z）    ← 点一下就跳到对应字母页
第 1 页：以该字母开头的常用字（44 个）
第 2 页：继续 44 个
...
```

**搜游戏的实际体验：**
```
搜「绿宝石」
  → 点 l   → 在第 1 页找到「绿」→ 点
  → 点 b   → 找到「宝」→ 点
  → 点 s   → 找到「石」→ 点
  → 搜索框 = 绿宝石 ✅
```

**优点**：改动小（只加数据 + 几十行逻辑）、纯 C、不需要改构建系统
**缺点**：要人工整理字表（可以用脚本按"游戏名用字频率"自动生成）

### 方案 B：全常用字分页

**设计：** 按使用频率把 3,500 常用字分 80 页，每页 44 字。

**优点**：能打任何字
**缺点**：翻 80 页找字很痛苦

### 方案 C：接 Android 系统输入法（**最彻底**）

**设计：**
- Java 侧：在 `RetroActivityFuture` 里调 `InputMethodManager.showSoftInput()`
- C 侧：通过 JNI 接收 IME 提交的文本，塞进 `input_keyboard_line`
- 复用 PR #14654 里 win32 用 imm32 的思路

**优点**：中文/emoji/任何语言都能打，体验和正常 App 一样 ✅✅
**缺点**：改动大（Java + C + JNI），要处理软键盘遮挡、生命周期

### 建议

**先做 A（1-2 天出成果），跑通了再考虑 C。**
A 做完也顺便验证了"中文页机制能工作"，为 C 打基础。

## 七、构建 RetroArch for Android 的门槛（必须先解决）

```bash
# 1. 装依赖
sudo apt install git build-essential
# Android SDK + NDK（NDK 约 3-5 GB）
#   ndk 版本：RetroArch 用 android-ndk-r23b 或更新

# 2. 克隆源码
git clone --depth 1 https://github.com/libretro/RetroArch.git
cd RetroArch

# 3. 编译 Android 版
./configure --enable-langextra          # ★ 确保 HAVE_LANGEXTRA
NDK=/path/to/android-ndk
cd pkg/android/phoenix
./gradlew assembleNormalUniversalRelease
# 产物：pkg/android/phoenix/build/outputs/apk/.../*.apk

# 4. 签名（或用 debug 签名测试）
apksigner sign --ks my.keystore app.apk
```

**耗时估计：**
- 环境搭建：2-4 小时（NDK 下载 + 首次编译踩坑）
- 首次编译：30-60 分钟
- 之后每次改动重编：5-15 分钟
